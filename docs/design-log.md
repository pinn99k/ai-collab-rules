## 1. 문제

AI에게 맡기면 구현은 빠르지만, 어디까지 무엇을 왜 만들었는지 따라가지 못했다. 설계 문서, AI가 쓰는 ADR, 기능 단위 개발을 시도했지만 모두 AI가 결정하고 AI가 기록하는 구조라서, 읽어도 이미 내려진 결정의 사후 해설에 그쳤다.

여기에 반복 개발에서 조잡한 코드가 누적되는 문제가 겹친다. 세션이 바뀔 때마다 AI의 맥락이 초기화되고, AI는 기존 코드의 패턴을 복제한다. 그래서 한 번 들어온 이상한 구조가 퍼진다. 결국 책임져야 할 코드를 설명할 수 없게 된다.

목표는 속도를 유지하면서, 어떤 코드든 설명할 수 있는 상태를 지키는 것이다.

## 2. 핵심 원칙

**결정은 문의 종류로 나눈다.** 되돌리기 비싼 결정(한쪽 문)은 사람이 내리고, 기존 패턴 안의 결정(양쪽 문)은 AI가 내린 뒤 기록한다. 새 추상화와 새 패턴은 작아 보여도 한쪽 문이다. 퍼지기 때문이다. 애매하면 한쪽 문으로 본다.

**검사는 회계 감사처럼 세 겹으로 한다.** 전수조사는 하지 않는다. 내부통제(규칙으로 예방), 분석적 절차(도구가 경보), 표본 검사(사람이 고른 곳만 직접 확인)로 나눈다.

**목표는 유도 가능성이다.** 모든 줄을 외우는 것이 아니라, 구조가 일관돼서 처음 보는 코드도 추론할 수 있는 상태다. 그래서 같은 일은 한 방식으로만 한다.

**이해는 예측이 빗나간 데서 생긴다.** 설명을 읽는 것이 아니라 직접 설명해 보고 틀린 곳을 교정받을 때 이해가 생긴다.

## 3. 결정 사항

| 항목 | 결정 |
|---|---|
| 변경 요약 | 커밋 단위 5줄. 숫자는 git이, 이유는 AI가 쓴다 |
| 경보 기준 | 이번 커밋에서 새로 생긴 것만. CC 10 초과, 새 중복, LOC가 예상의 2배 초과 |
| 실행 시점 | 매 커밋 직전 git 훅 + 주 1회 점검 |
| 경보 동작 | 경고만 한다. 차단하면 숫자 맞추기가 목표가 된다 |
| 측정 도구 | lizard(복잡도), jscpd(중복). 모든 언어 공통 |
| explain-back | 모드와 무관하게 항상 켠다. 한쪽 문 직후, 경보 diff, 하루 무작위 1건 |
| 모드 | learning / ship. 한쪽 문 범위만 바꾼다 |
| 구성 원칙 | 파일 하나에 목적 하나. 이름에 CLAUDE를 넣지 않는다. 스킬은 혼자서 완결된다 |
| 작성 원칙 | 금지 목록보다 할 일과 이유. 꼭 필요한 금지만 이유와 함께 남긴다 |

## 4. 구성

**md 규칙 (rules/)**: `~/.claude/rules/`에 설치하면 모든 프로젝트에서 매 세션 자동으로 읽는다.
- `ai-collab-coding-discipline`: Karpathy 4원칙 각색 + 일관성
- `ai-collab-change-summary`: 구현 전 예상 1줄, 커밋 요약 5줄
- `ai-collab-quality-alarms`: 경보 기준과 경보가 울렸을 때 할 일
- `templates/`: 프로젝트에 복사해 쓰는 CLAUDE.md, ARCHITECTURE.md

**스킬 (저장 완료)**: 필요할 때만 불러온다. rules/를 참조하지 않는다.
- `one-way-door`: 한쪽 문 판별 기준, 선택지 제시, 결정 대기, ADR 초안
- `explain-back`: 사용자가 2줄(왜 / 파급)로 설명하고 피드백 받기
- `weekly-audit`: 장황성·침식도 측정, 추세 비교, 단순화 후보 제시

스킬끼리는 `docs/explain-log.md`를 공유해 연결된다. one-way-door가 "대기"를 남기면 explain-back이 그것을 보고 발동한다.

**훅 (hooks/)**: 판단 없이 무조건 실행된다. 경고만 하고, 기록은 `.git/ai-alarms.log`에 남긴다.

## 5. 작업 흐름

1. AI가 예상 규모를 1줄 적는다.
2. 한쪽 문이면 one-way-door로 멈추고 사용자 결정을 받는다.
3. 양쪽 문이면 바로 구현한다.
4. 커밋 직전 훅이 지표를 측정하고, 경보가 울리면 3줄로 경고한다.
5. 커밋 요약 5줄을 남긴다.
6. 대상이면 explain-back을 한다.
7. 주 1회 weekly-audit를 한다.

## 7. 기각한 대안

- **모든 결정을 사람이 한다**: 구현 속도라는 장점이 사라진다.
- **모든 변경을 ADR로 남긴다**: 문서가 노이즈가 되어 아무도 읽지 않는다. ADR은 한쪽 문만 남긴다.
- **AI가 사고 흐름을 기록한다**: 그럴듯한 사후 합리화가 된다. 결정 이유는 사람이 쓴다.
- **AI에게 품질 점수를 매기게 한다**: 판단이 흔들린다. 경보는 결정론적인 도구가 울린다.
- **경보가 커밋을 차단한다**: AI가 지표 통과 자체를 목표로 삼게 된다.
- **스킬이 외부 md를 참조한다**: 경로가 없는 환경에서 스킬이 빈 껍데기가 된다.
- **커뮤니티 스킬을 그대로 설치한다**: 우리 기준과 맞지 않고, 훅 스크립트 보안 검토가 필요하다. 검증된 문구만 차용했다.
