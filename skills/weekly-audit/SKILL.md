# 주간 점검

사람이 직접 볼 곳을 고르는 점검이다. 수치는 경보로만 쓰고, 고칠지는 사용자가 정한다.

## 할 일
1. 측정한다. 도구 결과 전문 대신 요약 수치만 대화에 가져온다.
   - 장황성 = 중복 줄 수 / 전체 LOC (jscpd 리포트의 중복 비율)
   - 침식도 = CC 10 초과 함수의 mass 합 / 전체 함수 mass 합, mass = CC × √NLOC (`lizard --csv`의 NLOC, CCN 열로 계산)
   - 도구가 없으면 설치 방법(`pip install lizard`, `npx jscpd`)을 안내하고 멈춘다.
2. `docs/quality-trend.md`에 한 줄 추가한다: `날짜 | LOC | 장황성 | 침식도`. 지난 기록과 비교한다.
3. 단순화 후보 상위 3개를 제시한다: 함수, 수치, 왜 복잡한지 1줄.
4. `docs/explain-log.md`의 이번 주 건너뜀 비율을 보고한다.
5. ARCHITECTURE.md의 규칙과 실제 코드가 다른 곳을 보고한다.
6. 사용자가 고른 후보만 별도 커밋으로 단순화한다.

## 해석
- 절대값보다 추세를 본다. 수치가 올랐으면 원인 커밋을 찾아 함께 보고한다.
- 참고값 (외부 글 SlopCodeBench, 미검증): 사람이 관리한 저장소는 장황성 약 0.15, 침식도 약 0.31. AI 생성 코드는 약 2배.

## 보고 예시
```
주간 점검 2026-11-13
LOC 2,140 (+610) | 장황성 0.18 (+0.03) | 침식도 0.42 (+0.11)

단순화 후보
1. Parser.parseCommand — CC 17, NLOC 64: 명령별 분기가 한 함수에 몰림
2. Store.set — CC 12, NLOC 40: 만료·덮어쓰기·타입 검사가 섞임
3. Server.handle — CC 11, NLOC 52: 에러 처리가 경로마다 다름

explain-back 건너뜀: 2/9
ARCHITECTURE 불일치: 에러는 예외로 처리하기로 했으나 Store.set이 null을 반환
```
