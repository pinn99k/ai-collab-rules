# 한쪽 문 결정

되돌리기 비싼 결정은 사용자가 내린다. 이 스킬은 결정 재료를 짧게 정리하고, 결정을 기록으로 남긴다.

## 해당 여부
모든 모드:
- 자료구조, 저장 포맷, 스키마
- 프로토콜, 공개 API 형태
- 모듈 경계 변경, 새 모듈
- 외부 의존성 추가
- 새 추상화·새 패턴 도입 (다음 세션이 그 패턴을 복제해 퍼뜨린다)
- 기존 ADR과 다른 방향

learning 모드에서 추가:
- 핵심 알고리즘 선택 (예: 해시 vs 트리, 만료 정책)
- 동시성·에러 처리 전략
- 테스트 전략 변경

모드는 프로젝트 CLAUDE.md의 `MODE:` 값이다. 없으면 learning.
목록에 없는 결정은 바로 구현하고, 커밋 메시지에 결정을 한 줄 남긴다.

## 할 일
1. 코드를 쓰기 전에 아래 형식으로 제시하고 결정을 기다린다.
2. 결정을 받으면 `docs/adr/NNNN-<slug>.md`에 ADR 초안을 쓴다. "결정 이유"는 비워 둔다. 이유를 직접 써 보는 것이 사용자 이해의 핵심이다.
3. ARCHITECTURE.md가 있으면 ADR 목록과 해당 "단일 방식 규칙"을 갱신한다.
4. 구현 후 `docs/explain-log.md`에 `날짜 | ADR-NNNN 구현 | 대기` 한 줄을 남긴다. 이해 검사 대상 표시다.

## 제시 형식
**결정**: 무엇을 정해야 하는지 1줄

| 선택지 | 장점 | 단점 | 되돌리기 비용 | 영향 범위 |
|---|---|---|---|---|

**추천**: 하나와 이유
**PM 관점**: 비용, 유지보수, 확장 중 핵심 1줄

## 예시
상황: Redis 구현 중 키 만료 처리 방식이 필요하다.

**결정**: 만료된 키를 언제 지울지

| 선택지 | 장점 | 단점 | 되돌리기 비용 | 영향 범위 |
|---|---|---|---|---|
| 조회 시 삭제 | 구현 단순, 추가 스레드 없음 | 조회되지 않는 만료 키가 메모리를 차지 | 낮음 | 조회 경로 |
| 주기적 샘플링 삭제 | 메모리 회수 | 타이머·동시성 처리 필요 | 중간 | 이벤트 루프, 저장소 |
| 둘 다 (실제 Redis 방식) | 균형 | 구현량 2배 | 중간 | 위 둘 |

**추천**: 조회 시 삭제로 시작한다. 미니 프로젝트 규모에서는 메모리 압박이 없고, 나중에 샘플링을 더해도 기존 코드를 거의 바꾸지 않는다.
**PM 관점**: 테스트가 가장 쉬워 일정 위험이 낮다.
