# 한쪽 문 결정

되돌리기 비싼 결정은 사용자가 내린다. 이 스킬은 결정 재료를 카드 한 장으로 줄이고, 결정을 기록으로 남긴다.

## 해당 여부
모든 모드:
- 자료구조, 저장 포맷, 스키마
- 프로토콜, 공개 API 형태
- 모듈 경계 변경, 새 모듈
- 외부 의존성 추가
- 새 패턴 도입: 다른 코드가 따라 쓰게 될 방식 (다음 세션이 그 패턴을 복제해 퍼뜨린다). 파일 하나 안에서 끝나는 도우미는 해당하지 않는다
- 기존 ADR과 다른 방향

learning 모드에서 추가:
- 핵심 알고리즘 선택 (예: 해시 vs 트리, 만료 정책)
- 동시성·에러 처리 전략
- 테스트 전략 변경

모드는 프로젝트 CLAUDE.md의 `MODE:` 값이다. 없으면 learning.
목록에 없는 결정은 바로 구현하고, 커밋 메시지에 결정을 한 줄 남긴다.

## 할 일
1. 코드를 쓰기 전에 결정 카드를 내고 답을 기다린다. 질문은 한 번에 하나만 낸다. 프로젝트에 질문 지도(`docs/question-maps/`)가 있으면 그 질문의 카드로 적는다.
2. 답을 받으면 카드에 답 · 누가 정했는지 · 날짜를 적고, `docs/adr/NNNN-<slug>.md`에 ADR을 쓴다. ADR은 기록용이다. 카드의 내용을 옮겨 적고, 사용자에게 읽거나 채우라고 하지 않는다.
3. 사용자가 "추천대로"로 넘기면 추천안으로 진행한다. 답에 `위임`을 적고, `docs/explain-log.md`에 `날짜 | ADR-NNNN 질문 요약 (위임) | 대기 |` 한 줄을 넣는다. 위임은 정상 경로다. 표시를 남겨 나중에 다시 볼 곳을 알게 한다.
4. 사용자가 직접 고른 결정은 explain-log에 넣지 않는다. 고르는 과정이 이해 확인이다.
5. ARCHITECTURE.md가 있으면 ADR 목록과 해당 "단일 방식 규칙"을 갱신한다.

## 결정 카드 (5줄 이내)
```
**Q. 정할 것 한 줄**
- A: 이렇게 하면 → 이런 결과
- B: 저렇게 하면 → 저런 결과
- 추천: A. 이유 한 줄
```
- 선택지는 용어가 아니라 결과로 쓴다. 이름은 사용자가 고른 뒤에 붙인다. 용어를 모르면 고를 수 없기 때문이다.
- 되돌리기 비용이나 유지보수 비용이 선택을 가르면 그 선택지의 결과에 적는다.
- 선택지가 넷 이상이거나 비교 축이 여럿이면 카드 아래에 표를 덧붙인다. 카드만 읽어도 고를 수 있어야 한다.

## 예시
상황: Redis 구현 중 키 만료 처리 방식이 필요하다.

**Q. 기한이 지난 값을 언제 지울까**
- A: 누가 그 값을 찾을 때 확인하고 지운다 → 코드가 가장 단순하다. 아무도 안 찾는 값은 메모리에 남는다
- B: 일정 시간마다 몇 개씩 골라 지운다 → 메모리가 회수된다. 타이머와 동시 접근 처리가 필요하다
- C: 둘 다 한다 → 실제 Redis 방식이다. 구현량이 2배다
- 추천: A. 이 규모에서는 메모리 압박이 없고, 나중에 B를 더해도 기존 코드를 거의 안 바꾼다

사용자가 A를 고른 뒤: "A는 lazy expiration, B는 active expiration이라고 부른다."
