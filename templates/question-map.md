# 질문 지도 — 개발 범위 이름

> 기준 문서: 과제 원문 · 기획서 · 받은 설계 경로
> 종류: 질문 지도 | 빈칸 지도 (받은 설계가 남긴 것만)
> 상태: 결정 중 | 닫힘 (YYYY-MM-DD)
> 흐름 지도를 먼저 봤는가: 예 (YYYY-MM-DD)

## 명세 · 받은 설계가 이미 정한 것
- "명세 문장" → 그래서 고를 수 없는 것
- 받은 설계에서 온 것은 문서와 절을 적는다. 다시 묻지 않는다

## 지도
"묻기"는 아키텍처급만, 단계당 0~2개. 넘으면 단계를 나눈다.
```
Phase 1
Q1. 질문                  ← "명세 문장"       [묻기]
 └ Q2. 질문               (Q1 답에 달림)      [알려주기] 답 한 줄 → 흐름 #N
Q3. 질문                                      [맡기기] 답 한 줄
Phase 2
Q4. 질문                  ← "명세 문장"       [묻기]
```

## 실무 질문
명세 밖에서 현업이 묻는 질문 3~5개 (wide-map). 탐구용이라 묻기 개수에 세지 않는다. 하나에 `[깊게]`.
- 렌즈: 질문 → 바깥 지도의 어느 경계 · 답 3~5줄

## 결정 카드
"묻기" 질문마다 1장. 위에서부터 하나씩 닫는다.

### Q1. 질문
- A: 이렇게 하면 → 이런 결과
- B: 저렇게 하면 → 저런 결과
- 렌즈1: A는 ~, B는 ~
- 렌즈2: A는 ~, B는 ~
- 추천: A. 이유 한 줄
- 답: 고른 것 · 사람 | 위임 · YYYY-MM-DD (위임이면 흐름 지도에 `[위임 Q1]`)
- 이름: 고른 뒤에 붙이는 용어
