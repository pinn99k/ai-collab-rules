# 흐름 지도 — 프로젝트 이름

> 상태: 예정 (구현 전) | 실제 (Phase N 끝, YYYY-MM-DD)
> 사람이 작업 중에 읽는 문서 두 장 중 하나다. 왜 그렇게 정했는지는 질문 지도에 있다.

## 바깥 지도
이 시스템이 실제 운영에서 놓이는 자리. 개발 범위를 시작할 때 wide-map 스킬로 채운다.
우리가 만드는 상자, 이번에 안 만드는 것, 공격자 · 장애가 서는 경계를 표시한다. 깊게 팔 1개에 `[깊게]`.

```
클라이언트 → [경계] → [우리가 만드는 것] → [경계] → 저장소
                (이번에 안 만듦)
 ↑ 공격자 · 장애 위치
```

## 한 장 그림
요청 하나가 들어와서 결과가 나갈 때까지. 단계가 나뉘어도 그림은 하나다.
구현 전에는 모듈 이름으로, 구현 뒤에는 실제 파일과 함수 이름으로 쓴다.

```
1. 입구              받는 것
 → 2. 단계 이름      무엇을 무엇으로 바꾸는지
 → 3. 단계 이름      ...
 → 4. 출구           내보내는 것
```

## 화살표마다
| # | 어디서 (파일 · 함수) | 데이터 모양 | 락 · 상태 변화 | 실패하면 | 결정 |
|---|---|---|---|---|---|
| 1 | | | | | `[위임 Qn]` · `[알려줌]` · 비움 |

결정 칸: 사람이 "추천대로"로 넘긴 결정은 `[위임 Qn]`, AI가 정한 작동 원리는 `[알려줌]`. 단계 끝 explain-back은 표시가 붙은 화살표에서 고른다.

## 경로
기본 경로와 갈라지는 길을 따로 적는다. 예: 쓰기, 키로 읽기, 전체 훑기, 에러.

### 경로 A: 이름
1 → 2 → 3 → 4. 갈라지는 곳과 이유 한 줄.
