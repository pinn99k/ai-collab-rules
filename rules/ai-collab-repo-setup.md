# 저장소 점검

목적: 규칙을 켜는 스위치를 프로젝트 밖에 둔다. 프로젝트 CLAUDE.md가 없는 저장소에서도 규칙이 빠졌다는 걸 알게 한다.
출처: 미니 DBMS(2026-11-17 회고, 훅 미설치)와 mini-stack(2026-11-19 회고, CLAUDE.md · 훅 없음). 훅 확인 지시가 CLAUDE.md 안에 있어서, CLAUDE.md가 없는 저장소에서는 확인도 함께 꺼졌다.

이 파일은 `~/.claude/rules/`에 전역으로 설치해야 효과가 있다. 저장소 안에서 `@`로 불러오면 그 저장소에서만 돈다.

## 세션 시작
- git 저장소에서 작업하면 아래 둘을 확인하고, 없는 것만 한 줄로 알린다
  - 루트의 `CLAUDE.md`
  - 커밋 훅 `.git/hooks/pre-commit`
- 사용자가 이 저장소는 규칙 없이 간다고 하면 그 세션에서는 다시 알리지 않는다

## 새 저장소를 만들 때
작업 중에 저장소를 새로 만들면(`git init`, 통합 · 데모용 저장소 포함) 첫 커밋 전에 아래를 깐다.
1. ai-collab-rules의 `templates/CLAUDE.md`를 복사하고 `MODE:`를 사용자에게 묻는다. ai-collab-rules 위치를 모르면 사용자에게 묻는다
2. 커밋 훅 (ai-collab-rules README 4절 5번)
3. 다른 저장소의 설계를 이어받으면 원본 위치를 CLAUDE.md에 한 줄로 적는다. 설계 문서 사본은 만들지 않는다 (`ai-collab-design-briefing.md` 기록용 문서 절)

깔지 않기로 하면 그 이유를 첫 커밋 메시지에 한 줄 남긴다.
