# 변경 요약

목적: 흐름을 따라갈 수 있는 최소 기록을 커밋 단위로 남긴다.

## 구현 전 (1줄)
```
예상: 약 N줄, 파일 M개, 영향: <모듈>
```
- N은 테스트를 뺀 소스 줄 수다. 숫자만 `.git/ai-estimate`에 저장한다. 커밋 훅이 실제 소스 증가량과 비교한 뒤 파일을 지운다.

## 커밋 메시지 본문 (5줄 고정)
```
왜: <요청 또는 문제 한 줄>
결정: <양쪽 문 결정 요약 / 없으면 없음>
새 추상화: <[패턴] 또는 [도우미] 이름 — 존재 이유 / 없으면 없음>
삭제: <삭제한 것 / 없으면 없음>
예상 대비: 예상 N줄 → 실제 K줄, <차이 이유>
```

## 규칙
- 파일 목록과 증감 줄 수는 `git diff --stat`이 제공한다. 직접 쓰지 않는다.
- 새 추상화는 둘로 나눈다. [패턴]은 다른 코드가 따라 쓰게 될 방식이다. [도우미]는 파일 하나 안에서 끝난다.
- [패턴]은 만들기 전에 사용자가 정한다. 질문 지도에 질문으로 올리고 답을 받은 뒤 구현한다. 커밋에 [패턴]이 처음 나오면 순서가 틀린 것이다.
- [도우미]는 이 칸에 한 줄만 남긴다.
- 리팩토링인데 "삭제"가 없으면 이유를 적는다.
