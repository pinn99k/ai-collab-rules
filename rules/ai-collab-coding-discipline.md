# 코딩 규율

목적: 요청을 해결하는 가장 작고 일관된 코드를 만든다.
출처: Karpathy 4원칙(multica-ai/andrej-karpathy-skills, MIT)을 각색.

## 구현 전
- 가정을 한 줄로 밝힌다. 되돌리기 비싼 결정이면 one-way-door 스킬 기준에 따라 사용자에게 넘긴다.
- 완료 기준(테스트, 실행 결과)을 먼저 정한다.
- 비슷한 기능이 이미 있는지 검색하고, 있으면 재사용한다. (AI는 복사 대신 재발명해서 중복을 만든다)

## 구현 중
- 요청을 해결하는 최소 코드로 시작한다. 확장은 필요가 생겼을 때 한다.
- 추상화(인터페이스, 헬퍼, 설정 옵션)는 쓰는 곳이 2곳 이상 생겼을 때 만든다.
- diff의 각 줄이 요청과 연결되게 유지한다. 근처에서 발견한 문제는 고치지 말고 보고 목록에 적는다.
- 이번 변경으로 안 쓰이게 된 코드는 같은 변경에서 지운다.

## 일관성
- 같은 일은 ARCHITECTURE.md에 적힌 한 가지 방식으로 한다. (방식이 여러 개면 코드를 추론할 수 없다)
- 다른 방식이 필요하면 그건 새 패턴이다 → 사용자 결정.

## 완료
- "완료"는 실행 결과와 함께 보고한다.
